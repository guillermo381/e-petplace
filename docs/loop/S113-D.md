**Caché del `system` — una sola pieza, y por medición:**

| pieza | cachea | por qué |
|---|---|---|
| `presencia` | **sí** | única con `system`, y es constante (~9.950 chars ⇒ del orden de 2.000-2.800 tokens, sobre el mínimo de **1024** de Sonnet 5). Y **regenera**: `TOPE_REGENERACIONES=3` da ráfagas de hasta 3 llamadas con el mismo `system` en la ventana de 5 min; el break-even son 2. |
| `carnet` | no | el contenido **arranca con la imagen**, que cambia siempre: no hay prefijo estable. |
| `documento` | no | ídem. |
| `nota_clinica` | no | el prompt se arma con `especie`+`motivo` y viaja **concatenado con el dictado** en un solo bloque. |

*Encenderlo en las tres sería pagar 1,25× de escritura por entradas que nadie
lee. Las columnas `tokens_cache_*` de `ia_uso` son las que dejan confirmarlo o
revertirlo con número en el lote 1.*

**El error sale TIPADO con `estadoHttp` y `detalle`** para que **cada edge
conserve su código y su mensaje, letra por letra**. *Unificar la puerta no es
unificar la voz.* `detalle` nació de una necesidad medida, no de gusto:
`extract-documento` es la única que separa «no trae texto» (`error_modelo` 500)
de «no devolvió JSON» (422), y sin `detalle` migrar habría colapsado dos estados
que esa superficie distingue a propósito.

**Ley del registro: `registrarUso` no lanza nunca.** Hoy importa de verdad —
`ia_uso` **todavía no existe** (la crea E), así que cada llamada loguea el fallo
y **las cuatro edges siguen funcionando igual que hoy**. Eso es el diseño.
**Cero dato personal:** ni `mascota_id`, ni `user_id`, ni una línea de prompt.

## Lo que devuelve `extraerVacunasDeCarnet` (`@epetplace/api`)

`ResultadoWrapper<LecturaDeCarnet, CodigoErrorExtraccion>` — **cambió de forma**:
antes `data` era el array de vacunas; ahora son **dos canastos**.

```ts
interface LecturaDeCarnet {
  vacunas: VacunaExtraida[];
  plan_impreso: FilaPlanImpreso[];
}

interface VacunaExtraida {
  nombre: string;                              // única obligatoria
  fecha_aplicada: string | null;               // YYYY-MM-DD · sin día+mes+año ⇒ null
  fecha_proxima: string | null;                // sólo si está ESCRITA
  lote: string | null;
  laboratorio: string | null;                  // ⚠️ hoy NO se persiste
  via: ViaAdministracion | null;               // cerrado por el CHECK real
  veterinario: string | null;                  // antes veterinario_nombre_externo
  vencimiento_biologico: string | null;        // ⚠️ hoy NO se persiste
  tipo_vacuna: TipoVacuna | null;
  confianza: ConfianzaExtraccion;              // 'alta' | 'media' | 'baja'
  evidencia: EvidenciaAplicacion;              // qué probó la aplicación
}

interface FilaPlanImpreso { nombre: string }

type ViaAdministracion   = 'subcutanea' | 'intramuscular' | 'intranasal' | 'oral';
type TipoVacuna          = 'antirrábica' | 'múltiple' | 'tos de las perreras'
                         | 'leptospirosis' | 'giardia' | 'triple felina'
                         | 'leucemia felina';
type ConfianzaExtraccion = 'alta' | 'media' | 'baja';
type EvidenciaAplicacion = 'sticker_con_fecha' | 'sello' | 'manuscrito' | 'impreso';
```

Los siete nombres se exportan desde `@epetplace/api`.

## Para C — tres cosas, y la tercera es de producto

1. **`ext.data.vacunas`** donde antes era `ext.data`. Ya lo adapté al mínimo en
   `carnet.tsx` para que el árbol quede verde; la **pantalla** es tuya.
2. **`confianza` y `evidencia` viajan por fila** — son para la confirmación:
   una fila `baja` no se descarta, *se mira con atención*. `evidencia` dice
   **por qué** el modelo cree que se aplicó, que es lo que la persona verifica.
3. 🔴 **`plan_impreso` llega y no tiene pantalla.** Hoy, un carnet con 0
   aplicaciones y 11 renglones de plan sigue cayendo en `sin_vacunas` y **borra
   la foto**. Es exactamente el caso del carnet que devolvía doce, visto del
   derecho: *ese carnet no estaba vacío, estaba sin usar.* Decidir qué se le
   muestra a la familia es tuyo.

## Para A — un bloqueante nombrado

🔴 **`registrar_vacunas_de_carnet` no acepta `laboratorio` ni
`vencimiento_biologico`.** Las **columnas existen** en `evento_vacuna_aplicada`
(medido, no supuesto) y hoy están en **0/32**. Hasta que la RPC las acepte, los
dos campos se extraen, se muestran en la confirmación y **se pierden al
guardar**. *Se dice para que nadie los dé por guardados.*

Y una nota de forma, con su CHECK citado: la tabla tiene
`CHECK (vencimiento_biologico >= fecha_aplicada)`. Cuando esos campos entren,
**ese CHECK es el detector más barato del defecto del sticker** — un
vencimiento anterior a la aplicación es imposible, y significa que el modelo
confundió las dos fechas. Hoy no puede dispararse porque la RPC no los escribe.
